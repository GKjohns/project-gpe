# What the ETH paper proves, how, and where it is weakest
(API-only reading of proofmap.ink `eth`; 48 calls; companion log: eth_learner_log.md in the same directory)

## 1. The main theorem

**In my words (thm-main, Sec 1, proved in App. D.2-D.3).** Fix k >= 2. There is a deterministic algorithm which, given a k-CNF F on n >= 20 declared variables and m clauses, outputs the exact number #F of satisfying assignments using

  (n+m)^{O_k(1)} * 2^{O_k( n log log n / sqrt(log n) )}   bit operations and (n+m)^{O_k(1)} bits of space;

and if additionally m <= D n for a fixed D, the time is (n+m)^{O_{k,D}(1)} * 2^{O_{k,D}( n / sqrt(log n) )}.
Since exact counting decides 3-SAT, and both exponents are o(n), this contradicts ETH ("3-SAT needs 2^{Omega(n)} time"). All constants depend on k (and D); the algorithm is uniform and deterministic; "n >= 20" is a technical floor so that lambda = ceil(log2 n) is large enough for the parameter choices.

**The paper's own headline differs.** The abstract and the catalog description claim 2^{n/(log n)^{1/2+o(1)}}. The theorem proves n log log n / sqrt(log n) = n/(log n)^{1/2 - o(1)}, which is a *weaker* (larger) exponent. I searched the source for the abstract's form and found no statement proving it. Either the abstract has a sign slip in the o(1), or it describes a version of the paper the map does not cover. Both are 2^{o(n)}, so the ETH refutation is unaffected, but it is a sloppiness signal in the paper's front matter.

**Where the real theorem lives.** The actual engine is `thm-tensor-contraction` (App. D.1, classified novel):
Fix C, A, b. A bipartite Boolean tensor network with at most Cs edges, poly(s) vertices, maximum degree <= ceil(s^{9/10}), entries in (Z/2^{P0})[V]/(V^l) with 1 <= P0, l <= Cs, each entry computable in (s+L)^b 2^{A s^{9/10}} time and poly space, can be contracted deterministically in (s+L)^{O(1)} 2^{O(s/sqrt(log s))} bit operations and polynomial space.
Because a k-CNF with n+m = s is a bounded-degree bipartite Boolean tensor network with O_k(s) edges (claim-thm-main-1), the fixed-density case of thm-main is a two-paragraph corollary of this theorem. In complexity terms this theorem is far stronger than "ETH is false": it gives 2^{o(s)} exact counting for every bounded-arity #CSP with linearly many constraints (perfect matchings, colorings, permanents of sparse 0/1 matrices, ...). A reader should treat *this* as the claim under test.

## 2. Proof architecture (DAG of load-bearing steps)

Notation: lambda = ceil(log2 s) (or log2 n), nu = ceil(log2 lambda). "Paper class" is the map's standard/routine/novel label.

1. **k-CNF -> bipartite Boolean tensor network** (`claim-thm-main-1`, D.2). One vertex per clause with its satisfaction table; equality trees of trivalent tensors for variables; subdivide every edge by a binary equality tensor to make it bipartite. O_k(n+m) edges, max degree max{k,3}, contraction = #F. Rests on nothing. Class: routine. I agree (textbook).

2. **Fixed-density case of thm-main** (`claim-thm-main-2`, D.2). Apply step 6 over Z/2^{n+1} with s = n+m, P0 = n+1, l = 1; read off #F as the least residue. When m <= Dn, s = O(n), exponent O(n/sqrt(log n)). Rests on 6. Class: routine. Agree.

3. **Sparsification** (`lem-sparsify`, App. A; uses lem-spar-branch, lem-spar-marked-degree, lem-spar-insertion-bound). IPZ/Calabro-Impagliazzo-Paturi style: for rational sigma, a tree of poly(n,1/sigma) 2^{sigma n} k-CNFs with disjoint satisfying sets, each leaf with variable occurrence <= B = O_k((sigma^{-1} log(2/sigma))^{k-1}). Used with sigma = 1/ceil(sqrt(lambda)) so 2^{O(n/sqrt(log n))} leaves, B = lambda^{O_k(1)}, <= Bn clauses per leaf (`claim-thm-main-3`). Class: routine (standard with bookkeeping). Agree; this is the well-trodden part.

4. **Leaf counting via parity checks + greedy hashing** (`lem-sparse-checks` Sec 6.1, `lem-greedy-hashes` Sec 6.2; `claim-thm-main-4`). Build an explicit Tanner/expander code parity-check matrix A^(0) with <= 3n rows, D0 = 320000 B^2 mu^3 ones per row, kernel vectors of support >= m/P (P = 20000 B^2 mu^2); then greedily append 3n rows, choosing each by minimizing a common-zero count N(A; h) over (2m)^P candidates, so that N(A) = #F for the leaf. Each counting query is a system of <= 6n degree-<= k F2-polynomials with lambda^{O_k(1)} monomials; there are 2^{lambda^{O_k(1)}} queries per leaf. Class: routine (expander codes + conditional expectations). Mostly agree; the reduction "count of a sparse k-CNF = count of a sparse polynomial system with a few extra parity rows" is clever but built from standard pieces. The map flags that lem-greedy-hashes' dependence on lem-sparse-checks is inferred, not an edge.

5. **Counting common zeros of sparse low-degree F2 systems** (`lem-tensor-sparse-query`, D.3, novel; uses `lem-rational-idempotent` 5.1, `lem-total-order` 5.2, and step 6). Branch on the few high-incidence variables (2^{n/sqrt(lambda)} branches); lift each equation's parity indicator to an integer polynomial in V truncated mod V^l (the "h-expansion"/truncated-product trick of Sec 5); index the monomials of the product by Boolean wires so the whole sum becomes a sum over 2^{O(sqrt n log n)} bipartite networks with M = O_{k,c}(n nu) wires and degree n^{3/4} lambda^{O(1)} (`claim-lem-tensor-sparse-query-3`); contract each with step 6 at s = n nu. Result: n^{O(1)} 2^{O(n log log n/sqrt(log n))}. Class: novel (map) -- I would call it routine-given-step-6: the only new idea is reusing step 6; the lifting lemmas are elementary. This step is where the log log n enters (s = n nu).

6. **Subexponential bipartite tensor-network contraction** (`thm-tensor-contraction`, D.1/D.4, novel). The engine. A recursion with parameters per depth d: u_d = floor(eps lambda/2^d), a_d = 2 sum_{j<=d} u_j, L = 2^a, D_arr = r^{2a} (r = 64 groups), Delta = ceil(s^{9/10}), leaf when M <= H edges. At an active call on a network with M edges:
   6a. **Packing** (`lem-tensor-packets`, D.4.2, routine): label vertices by [r]^a, embed edges into <= 3M/L packets of L slots, balanced per coordinate (method of conditional expectations). I agree it is routine.
   6b. **Cauchy deformation and integrality** (`lem-tensor-integrality`, D.4.3, routine): replace the edge-equality constraints by a one-parameter deformation F(T) = sum_{X,Y} A(Y)B(X) prod_x l_{Y_x}((W(T)X)_x) (eq. D.? at line 197), with F(0) the true contraction; entries at T = t + alpha z (t in a 2-adic grid S, alpha, z in a degree-e = 4 lambda Galois-ring extension) stay integral. Routine given the setup.
   6c. **Mode expansion and mode budget** (prose D.4.4, eqs D.13-D.15, NOT a node): expand W_xy(t+alpha z) geometrically in powers b; for each packet, tile and b introduce a mode variable Z of weight w_Z = b+1 standing for L_Z(X) = sum_{columns y in tile} j^b X_y; the coefficient of Z is divisible by 2^{w_Z}; in the product of affine row factors every monomial Z^beta has coefficient divisible by 2^{sum w_Z beta_Z}, so modulo 2^{p_t} only tuples with sum w_Z beta_Z < p_t survive; with <= 6M/D_t modes per weight the number of surviving tuples is exp(O(sqrt(M p_t/D_t))) = exp(O(M/sqrt u)) (D.15). This partition-number bound is the whole source of the subexponential saving.
   6d. **Recursion identity and children** (prose D.4.5-D.4.6, eq D.16, NOT a node): F(t+alpha zeta) = sum_beta prod_{g=1}^{64} Z_{g,beta} mod 2^{p_t}, where Z_{g,beta} is the contraction of a child network (group-g vertices on one side, one vertex per packet on the other; child has 6M/r = 3M/32 < M/8 edges; packet vertices have <= 2L ports and carry the Z^beta coefficient extraction and the L_Z(X)^{beta_Z} factors).
   6e. **Tapered Hermite recovery** (`lem-tapered-hermite`, D.4.4, routine per map): recover F(0) mod 2^p from F(t+alpha z) mod 2^{p_t}, p_t = p + 8hD_t + 8M(a+1), using only the first q_t = h max(0, u - v_2(t)) Taylor coefficients at each node t; 2-adic loss of the Lagrange/Hermite weights E_t(0) is >= -6 D_t h (`claim-lem-tapered-hermite-3`). The taper (q_t = 0 when v_2(t) >= u) is what keeps D_t >= 2^{a-u} polynomially large, so the inherited precision stays below M D_t/u and the mode budget stays exp(O(M/sqrt u)). I checked this arithmetic by hand from the fragments and it is self-consistent.
   6f. **Assembly** (`claim-thm-tensor-contraction-1..4`, D.4.7): children per active depth-d call <= s^{O(1)} exp(O((s/sqrt lambda)(sqrt2/8)^d)); O(log lambda) depths; total calls exp(O(s/sqrt lambda)); leaf cost 2^H * 2^{O(s^{9/10})} = exp(O(s/sqrt lambda)); depth-first traversal gives poly space.
   Class: novel (map). Agree it is novel; disagree with the map that 6e is "routine" -- the paper's own citation in thm-tensor-contraction calls tapered Hermite recovery and integral local coordinates its *new* lemmas, and the taper is load-bearing.

7. **Arbitrary-density assembly** (`claim-thm-main-5`, D.3): costs of steps 3+4+5 multiply to (n+m)^{O(1)} 2^{O(n log log n/sqrt(log n))}; leaf counts add in an (n+1)-bit accumulator. A combined algorithm (lines 363-369) uses step 1+2 when m <= n nu and steps 3-5 otherwise. Routine. Agree.

8. **Consequences** (`cor-quantitative-circuits`, `cor-consequence-circuits`, `cor-consequence-local-inversion`, `cor-max-sat-approximation`, `cor-graph-counting`): E^NP needs > c n sqrt(log n) gates infinitely often (Williams-style, external results), etc. Routine. Agree; nothing hinges on them.

**Not load-bearing.** Sections 3-5 of the body ("shared linear summaries", `def-layout`, `def-overview-measurement-structure`, `prop-general-count`, `thm-overview-sparse-polynomials`, `prop-interpolation-bound`) prove a *weaker* 2^{O(n (log log n)^2/sqrt(log n))} algorithm by a related measurement/replacement-form construction. `trace` finds no path from any of them to thm-main in either direction, and the LaTeX of claim-thm-main-1..5 cites only Appendix D, A, 5.1-5.2 and 6.1-6.2. Two of the paper's five "novel" nodes are in this dead branch. The paper is effectively two papers: a long body with a weaker result, and an appendix that supersedes it.

## 3. Where it is most likely wrong or hand-wavy

**(a) The recursion identity and the children, D.4.5-D.4.6 (no node; eq D.16, quantitative-contraction.tex ~484-529).** This is the only genuinely new mathematics and it is argued in one sentence: "substitution for each mode depends only on bits in its source group. Distributing the product in [eq D.?], and then summing the independent bits within groups, proves the exact identity F(t+alpha zeta) = sum_{beta: sum w_Z beta_Z < p_t} prod_{g=1}^r Z_{g,beta} (mod 2^{p_t}), where Z_{g,beta} is the contraction of the child just defined. The omitted monomials vanish by their coefficient divisibility." For this to factor over groups, every mode must have a single source group and a single target group, every row's non-local coupling must be expressible through modes of its own packet only (i.e. W(T) must be block-diagonal by packet, which I could not confirm), and the packet vertex must be able to compute "the coefficient of Z^{beta|packet} in the product of its target rows' affine factors times prod L_Z(X)^{beta_Z}" from its <= 2L ports. The map's own friction note says the proof "only assembles the algorithm" and the key identity is "argued in unlabeled text". If the paper is wrong, this is the first place I would look: a cross-term between modes of different packets, or a row whose coupling is not confined to one packet, breaks the factorization and the whole exponent.

**(b) The mode budget / partition count, D.4.4 (eqs D.13-D.15, lines ~416-470).** "There are at most (3M/L)2^{i+1} = 6M/D [modes] ... the number of these tuples is exp(O(sqrt(M p_t/D))) = exp(O_C(M/sqrt u))." The equality needs p_t = O(M D_t/u) (D.11) for *every* active node t, including the inherited precision p from the parent. I reconstructed that the taper makes this hold, but the paper's precision bound p <= s lambda^{O(1)} 2^{a_{d-1}} is also unlabeled prose, and the generating-function estimate ("For any theta > 0, the generating product and [D.14] bound the number by ...") is cut off from me. An off-by-a-log in the count of modes per weight (e.g., if the number of distinct powers b that survive is ~p_t rather than bounded) would turn exp(M/sqrt u) into exp(M), which is exactly brute force. This is the second-most-likely failure point, and it interacts with (a).

**(c) The claimed entry-computation budget and the degree hypothesis.** thm-tensor-contraction allows entries computable in 2^{A s^{9/10}} time and vertices of degree s^{9/10}; the children add packet vertices with <= 2L <= s^{1/1000}... ports whose entries involve Z^beta coefficient extraction over up to L rows with mode exponents up to p_t = poly(s). The verbatim proof says only "Local arithmetic, packing, descriptions, and recovery use polynomial time per generated term" (lines 596-600). Whether the packet-vertex entries really are computable within the hypothesis of the *inductive* call (needed for `claim-thm-tensor-contraction-1`, "correct at every call") is asserted, not shown, in anything a node covers. Less likely to be fatal than (a)/(b) -- an overrun here would cost a factor, not the exponent -- but it is where "routine" bookkeeping hides.

Minor: the abstract's 2^{n/(log n)^{1/2+o(1)}} is not what thm-main proves (Sec 1).

## 4. Verdict on "slop"

I cannot call it slop from what the API let me read, and I cannot call it correct either. It is *not* slop in the sense of incoherent symbol-pushing: the parameter system in Appendix D (u_d, a_d, L, D_arr, Delta, the taper q_t, p_t, the 6M/D mode count, the (sqrt2/8)^d telescoping) is internally consistent when I redo the arithmetic from the fragments, the standard parts (sparsification, expander-code parity checks, Hermite interpolation, Williams-style lower bounds) are stated with correct constants and classified honestly as routine, and every summary I checked against the LaTeX was faithful. What makes me deeply suspicious is structural rather than local: (i) the result is vastly stronger than "ETH is false" -- a 2^{O(s/sqrt(log s))} deterministic contraction of *any* bounded-degree Boolean tensor network -- and such strength usually has a simple bug; (ii) the only novel mathematics (D.4.4-D.4.6) is written as unlabeled prose that the proof of the main theorem merely "assembles", exactly where a machine-written paper would be most likely to assert a factorization that does not hold; (iii) the body (Secs 3-5, ~half the 67 pages) proves a superseded weaker result by a parallel construction and is disconnected from the headline, which reads like an unedited history of attempts rather than a paper; (iv) the abstract overstates the proved bound. My honest posterior: much more likely wrong than right, with the error most likely in the exactness of eq D.16 or the mode count D.15, but I could not exhibit a specific false step through the API.

A `read_source?file&from&to` or `read_section` tool, or nodes for the unlabeled identities, would have let me check (a)-(c) above.
- The definition of H (leaf threshold) and the exact meaning of D vs D_t vs D_arr in D.11/D.15; a glossary or `search_paper` with wider context (+-10 lines) would have done it.
- Whether W(T) is block-diagonal by packet (needed for the factorization in (a)).
- What the Lean formalization (hasLean: true) covers: statement only, sparsification only, or the contraction theorem. A `lean` field with scope per node would settle it; as is, "has Lean" conveys almost nothing.
- Whether the abstract's 2^{n/(log n)^{1/2+o(1)}} is a typo or a lost sharper theorem (no hit in search; a search that reports normalized query would help).
- How the body's weaker algorithm relates to the appendix (is Appendix D a later rewrite?); the paper's own Sec 2 overview text is not a node and I could not read it.

1. The crux of the paper is in unlabeled prose that no node covers; I could only read it through +-2-line search windows (log 13-19, 28-41, 42-47). ~25 of 48 calls were spent on this keyhole reading and I still have maybe a third of the text.
2. No way to ask "which nodes are load-bearing for thm-main"; had to infer from claim section ids, ancestors, and two negative traces (log 3, 5, 11-12).
3. `main_results` listed only thm-main; the engine thm-tensor-contraction, which is where the paper lives or dies, had to be discovered (log 2, 7-9).
4. 71 friction notes, 61 of them `inferred_dep`, mostly long "critique: ... DAG has no edge" text; no per-node counts or severity histogram in overview or list_nodes (log 6, 28-41).
5. Map classification inconsistency: thm-tensor-contraction's cite calls tapered-Hermite and integrality the paper's "new" lemmas, but both nodes are `routine` (log 28-41, 42-47).
6. Search hits mix files without naming them (line "1365|" from main_full_version.tex next to "11|" from quantitative-contraction.tex) and have `location: null` (log 13-19, 28-41).

8. Catalog endpoint uses camelCase (`hasLean`, `pdfUrl`) while paper endpoints use snake_case (`has_lean`, `pdf_url`); my first jq against /families/378 returned nulls (log 20-27, 48).
9. `ancestors` returns flat levels without parent pointers, so I could not see which depth-2 node hangs off which depth-1 node without more calls (log 5).
